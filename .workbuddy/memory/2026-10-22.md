## Java 课程站：架构选型结论 + 后端打通

### 架构判断（用户曾质疑是否该用非结构化数据库）
结论：**不切换到NoSQL**。核心实体强关系（course→module→lesson、user→progress、chat_session→message），
V8R6 实测原生支持 tsvector+GIN、jsonb、float4[]、物化视图、窗口函数、ON CONFLICT，
足够承载半结构化内容。仅 `vector` 扩展与 `zhparser` 不可用。
路线：关系型为主 + jsonb 文档列 + embedding 存 float4[] 应用层算余弦 + 万级规模时外挂向量库。

### 本轮修的问题
1. **`CourseService.getLesson` 用错方法** —— 用 `findLessonBySlug`（不含 content 正文）
   导致课时页正文只有 45 字符。改用 `findLessonDetail`。
2. **后端返回结构是平铺的** —— 课程信息在顶层而非 `detail.course` 嵌套，模块树是兄弟键。
   前端统一写 `(detail.course || detail)` 兼容。
3. **`/api/modules` 不含 lessons** —— 首页原本用它导致课时列表空白，改为一次调
   `/course/{slug}` 取全树。
4. **npm 权限问题** —— `E:\nodejs\node_cache` 不可写，须用 `npm install --cache ./.npm-cache`。
5. **Java 单文件模式读不了带中文的 Windows 路径** —— 报AccessDenied。
   必须在 `kb_env.sh` 里先把 SQL 拷到纯 ASCII 路径（`C:/Users/<user>/kbtmp`）。
6. **Java stdout 在中文 Windows 是 GBK** —— Python subprocess 需 `encoding="gb18030"`，
   否则 UnicodeDecodeError。
7. **课程正文太空** —— 原始 seed.sql 里 content 只是单段摘要（平均 72 字符），
   Markdown 渲染器无标题/代码块可渲染。新写 `scripts/enrich_content.py`，
   为 42 个课时逐节定制「本节要点/核心概念/关键代码/常见误区/动手练习」五段式正文，
   平均长度 72 → 658 字符，并同步刷新 search_index.body_text。
   注意：slug 必须查数据库实际值，作者猜的 `lock-mechanism`/`threadpool` 等
   实际是 `lock-mechanisms`/`thread-pool`。
